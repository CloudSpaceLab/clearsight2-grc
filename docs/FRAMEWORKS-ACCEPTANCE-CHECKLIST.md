## Inspection findings

- The v2 Framework Library contains an Explore view, search, jurisdiction and industry filters, selected-edition details, an external source link and loading/error/empty states. These behaviors are implemented in code but populated behavior has not been verified in the current local session.
- The running app shows **Catalog unavailable**. The v2 page fetches `/api/v1/frameworks`, a route implemented by the v2 Go server; the active local setup proxies `/api` to v1 instead. In a local unauthenticated probe, that route returned 404; v1's `/api/v1/framework-catalog/editions` returned 401, as its handler requires a session and a legal entity. These observations identify a route mismatch, not proof that the v1 catalog contains published editions.
- The v2 page expects a specific metadata-only catalog shape (`seed_revision`, `total`, source and license status and empty requirements); the v1 edition endpoint returns `{items}` and accepts jurisdiction and cursor/limit. A safe adapter must use the real v1 response and not equate different kinds of catalog records without checking their meaning, source rights and availability.
- The v1-connected app now uses the v1 edition endpoint and preserves the existing v2-server library for the other mode. A signed-in local Chief Risk Officer saw no published editions returned for GLOBAL and NG. Mobile light/dark and tablet empty states were checked, including a mobile overflow correction. Populated records, pagination and adoption remain unverified against the local database.
- A read-only database count found no published editions in any jurisdiction. A v1-connected adoption screen has been added for selecting a Program, proposing and reviewing adoption, and proposing/reviewing mappings; the workflow is not yet verified end to end against a published edition. Questionnaire linking, draft saving, edition updates, regulator management, and framework publication remain unavailable. The existing prototype's visual and interaction parity remains to be verified.
- In v2, **In my Programs**, **Edition updates**, **Add framework**, **Manage regulators** and **Review adoption** are disabled. Program workspace currently says frameworks and forms are not connected.
- v1 source exposes edition listing, Program adoption proposal/approval/rejection, mapping candidate/list/propose/approval/rejection routes, with Program authority and revision checks. These routes are code-level evidence only; current data, permissions, UX coverage and end-to-end behavior still require verification.
- The library prototype includes Explore, In my Programs, Edition updates, filters, selected details, source and adoption actions. The adoption prototype includes Program/scope, requirement links, questionnaire, review and save/send actions. Their example values and browser simulation are not production functionality.
- `docs/FRAMEWORK-PUBLICATION.md` documents source checksum verification and independent review requirements; it states no HTTP publication route is exposed for the v2 boundary. v1 publication capabilities and governance need separate confirmation before enabling creation or regulator administration.
